### 004 architectural decisions

- **Role catalogue (closed three-entry set, no permission engine)**:
  - `cashier` = **Cashier / Operator** — day-to-day terminal user.
  - `manager` = **Shift Manager** — floor-level supervisor with shift-review and forced-close authority.
  - `admin` = **Owner / Admin** — tenant-level authority.
  - 1:1 machine-identifier ↔ business-name correspondence (FR-002). 004 introduces no custom permission engine, ABAC system, or capability registry (FR-002a).
- **Identity model**: Clerk remains the **sole human identity provider** (Constitution Principle VIII, preserved). Every operator has a stable Clerk-backed identity. Manager/admin authentication is Clerk/password end-to-end. **Cashier PIN is a local terminal unlock factor only** (AD-2) — not an identity provider, not consulted by any backend endpoint, not the audit-attribution key. PIN compromise on a terminal does not compromise backend-facing identity.
- **Session policy**: single active operator session per operator branch-wide. Concurrent sign-in on a second terminal triggers an explicit takeover prompt; on confirmation the prior session ends with `end_cause = 'superseded_by_takeover'` and the takeover is recorded as an audited sensitive action (`operator.session.takeover`).
- **Shift policy**: operator-bound and **non-transferable** — no cashier handover. The cashier who opens a shift is the only cashier who closes it via the normal path.
- **Forced close** is a **distinct manager-attributable** recovery action (`shift.forced_close`, separate audit category from `shift.close`); records both the absent cashier (`shift_owner`) and the executing manager/admin (`forced_close_actor`); preserves blind-close discipline (cashier's `declared_count` recorded as **null / absent**, distinct from zero, distinct from matched).
- **Bridge-surface enforcement** (AD-1): every operator-aware bridge handler self-gates against `currentSession.role` at the main-process side. Renderer route guards are secondary UX defence only. Trust-boundary enforcement lives at the preload bridge per Constitution Principle III.
- **Offline behaviour — fail-closed for new sign-in** (NFR-011, added 2026-05-05): 004 fails closed for any new operator sign-in attempt while offline. Manager/admin sign-in is unavailable (Clerk unreachable); cashier PIN unlock alone is insufficient (the Clerk-anchored identity validation and Endpoint 6 takeover-detection step both require connectivity); takeover detection is unavailable offline. Existing already-signed-in local sessions MAY continue with the connection-state visual surfacing `offline` / `degraded` per 003; backend-dependent actions surface the existing `no_connection` UX without optimistic success (P2). Cashier-Forbidden Information catalogue items remain cashier-forbidden offline (NFR-004 deterministic role boundary). Local sign-out and inactivity auto-sign-out (FR-008 / FR-009) MAY still terminate the current session offline. Full offline operator sign-in is deferred to a future offline-auth feature.
