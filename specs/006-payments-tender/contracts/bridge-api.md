## Bridge gating — `requireOperatorSession`

Every handler in the `payments.*` and `tender.*` namespaces MUST
begin with:

```text
const session = requireOperatorSession({
  role?: 'cashier' | 'manager' | 'admin',
  payment_attempt_id?: string,
})
```

The helper lives in `src/main/payments/` (post-§A4) and delegates to
004's `src/main/operator/role-enforcement.ts`. Failure modes (mirrors
005's `cart.*` gating pattern):

| Condition | Result |
|:--|:--|
| No active session | `{ kind: 'refused', reason: 'no_session' }` per 004 FR-005 / FR-016. |
| Wrong role for this handler | `{ kind: 'refused', reason: 'role_denied' }`. |
| `payment_attempt_id` given but attempt's `operator_session_id` does not match `session.operator_session_id` AND handler is not in the manager-attributable set | `{ kind: 'refused', reason: 'wrong_owner' }`. |
| Tenant / branch / terminal mismatch between session and attempt | `{ kind: 'refused', reason: 'tenant_isolation' }`. |
| Attempt in terminal state (`settled` / `cancelled` / `failed` / `force_failed`) AND handler is mutating | `{ kind: 'refused', reason: 'attempt_terminal' }`. |
| Bound envelope's `cart_id` no longer in `frozen_handed_off` (cart consumed / cancelled / etc.) | `{ kind: 'refused', reason: 'cart_lost' }` or `{ kind: 'refused', reason: 'stale_handoff' }` depending on 005's cart state. |

**All refusals use generic wording.** No factor-distinguishing
variants (004 NFR-003 / PR-2 inherited; spec FR-022). The refusal
`reason` lives in the bridge payload for diagnostic logging (with
redaction); it is NOT echoed to the cashier as-is (the renderer
translates each reason to a generic "this action isn't allowed
right now" UX). See [../research.md](../research.md) R-2 for the
004-vs-005 reconciliation behind choosing `reason` over `category`.

## Idempotency — `idempotency_key` (UUID v4)

Every **mutating** handler accepts an `idempotency_key: string`
(UUID v4) generated by the renderer at the moment of intent. The
bridge handler (mirrors 005's `cart.*` idempotency contract; see
[../research.md](../research.md) R-10):

1. Looks up `payment_action_outbox` by `action_id = idempotency_key`.
2. If found AND the payload hash matches: no-op; returns the
   original outcome (Constitution §P5).
3. If found AND the payload hash differs: refuses with
   `{ kind: 'refused', reason: 'idempotency_payload_mismatch' }`.
4. If not found: applies the action AND writes the outbox row in the
   same SQLite transaction.

The renderer MUST NOT generate a new `idempotency_key` on retry —
the same UUID must accompany every retry of the same intended
operation.

## PaymentAttempt FSM

```text
idle → started (via payments.start)
started → settled (via payments.confirm, gated on settlement invariant)
started → cancelled (via payments.cancel)
started → failed (main-side detection: cart_lost, operator_session_terminated, dependency_unavailable, etc.)
started → force_failed (via payments.forceFail — Slice 4, manager-only)
```

Terminal states block all further mutation.

## TenderLine FSM (see [../research.md](../research.md) R-11)

```text
applying → applied (via tender.apply success)
applying → refused (via tender.apply refusal)
applied → reversed (via tender.reverse on cash / external_card_terminal; voucher reverse success)
applied → reversal_pending (voucher reverse on unreachable authority)
reversal_pending → reversed (Slice 4 deferred-reversal resolver)
```

`refused` is terminal — the cashier must add a new line, not retry
on the same `tender_line_id`.

## `payments.*` namespace

### `payments.start`

Creates a new payment attempt against a frozen `PaymentIntentEnvelope v1`.

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3.

**Request:**

```text
{
  envelope_handoff_action_id: UUID v4,   // from 005 cart.handoff return value
  envelope_cart_id: UUID v4,
  envelope_subtotal_minor: integer,
  envelope_version: 'v1',
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', payment_attempt_id: UUID v4 }
| { kind: 'refused', reason: 'no_session' | 'role_denied' | 'tenant_isolation' | 'cart_lost' | 'stale_handoff' | 'attempt_already_started_on_terminal' | 'idempotency_payload_mismatch' }
```

**Effects:**

- Writes `payment_attempts` row with `state = started`.
- Writes `payment_action_outbox` row with `action_kind = payment.attempt.start`.
- **No audit emission yet** — `payment.*` audit categories fire on
  terminal transitions only (FR-025).
- The partial unique index `(terminal_id) WHERE state='started'`
  catches concurrent `payments.start` attempts on the same terminal
  with refusal `attempt_already_started_on_terminal`.

### `payments.confirm`

Confirms a `started` attempt and transitions it to `settled` after
validating the settlement invariant.

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3.

**Request:**

```text
{
  payment_attempt_id: UUID v4,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', settled_at: UTC timestamp }
| { kind: 'refused', reason: 'no_session' | 'role_denied' | 'wrong_owner' | 'attempt_terminal' | 'tender_underpaid' | 'internal_error' | 'idempotency_payload_mismatch' }
```

**Effects (transactional):**

- Validates settlement invariant:
  `Σ payment_tender_lines.amount_applied_minor (where state='applied')`
  `== payment_attempts.envelope_subtotal_minor`.
- For each `internal_voucher` `TenderLine` in `applied` state: calls
  `vouchers.redeem` (Contract V-A) using the line's
  `voucher_redemption_intent_token`. On success: stores the returned
  `voucher_authority_redemption_id` on the line. On
  `dependency_unavailable`: attempt resolves to `failed`, voucher
  line transitions to `reversal_pending`, deferred resolver picks
  up later.
- On settlement-invariant success: transitions `payment_attempts.state
  = settled`, sets `settled_at`, writes `payment_action_outbox` row,
  emits `payment.settled` audit event with full tender breakdown
  (per AD-9 / R-8).

### `payments.cancel`

Cancels a `started` attempt; reverses every applied `TenderLine` per
FR-006B / R-13 (LIFO order); returns the surface to tender selection.

**Roles:** `cashier`, `manager`, `admin` (cashier-permitted per FR-020).
**Slice:** 3.

**Request:**

```text
{
  payment_attempt_id: UUID v4,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', cancelled_at: UTC timestamp, reversed_tender_line_ids: UUID[], reversal_pending_tender_line_ids: UUID[] }
| { kind: 'refused', reason: 'no_session' | 'role_denied' | 'wrong_owner' | 'attempt_terminal' | 'idempotency_payload_mismatch' }
```

**Effects (transactional):**

- LIFO-iterates `applied` `TenderLine`s by `apply_order DESC`.
- For each:
  - `cash` → transition to `reversed`; no till impact recorded;
    emit `tender.reversed`.
  - `external_card_terminal` → transition to `reversed`; emit
    `tender.reversed` with a `manual_void_required: true` flag in
    the audit payload (cashier-facing UX shows a generic "void on
    the terminal" reminder).
  - `internal_voucher` → call `vouchers.reverse` (Contract V-A).
    Success → transition to `reversed`; emit `tender.reversed`.
    Failure (`dependency_unavailable`) → transition to
    `reversal_pending`; emit `tender.reversal_pending`. Slice 4
    deferred resolver picks up later.
- Transitions `payment_attempts.state = cancelled`; emits
  `payment.cancelled`.

### `payments.forceFail` *(Slice 4 only)*

Manager / admin force-fails a stuck `started` attempt.

**Roles:** `manager`, `admin`. **Cashier MUST be refused** with
`role_denied` (FR-021).
**Slice:** 4.

**Request:**

```text
{
  payment_attempt_id: UUID v4,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', force_failed_at: UTC timestamp }
| { kind: 'refused', reason: 'no_session' | 'role_denied' | 'attempt_terminal' | 'idempotency_payload_mismatch' }
```

**Effects (transactional):**

- Transitions `payment_attempts.state = force_failed`; sets
  `force_failed_at`; sets `force_fail_attribution_operator_id` to
  the manager's Clerk identity; sets `failure_reason =
  'force_failed_by_manager'`.
- Emits `payment.force_failed` audit event with **dual attribution**:
  `attribution_operator_id` = the cashier who started the attempt;
  `force_fail_attribution_operator_id` = the manager. **Manager
  identity is never echoed to cashier-visible UI** (FR-021 last
  clause).
- Already-`applied` `TenderLine`s are left in `applied` state — they
  are not auto-reversed by force-fail. Manager incident-response UX
  may offer per-line reverse buttons as a separate action (Slice 4
  follow-up).

### `payments.subscribe`

Renderer subscribes to attempt-level + per-line state changes for
the current attempt. Push-only; no mutation. Returns minimised
state (FR-017 voucher minimisation).

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3.

**Request:** `{ payment_attempt_id: UUID v4 }`.

**Response (stream):**

```text
{
  payment_attempt: {
    payment_attempt_id, state, started_at, settled_at?, cancelled_at?, failed_at?, force_failed_at?,
    envelope_subtotal_minor,
    tender_lines: TenderLineRendererView[]
  }
}

TenderLineRendererView {
  tender_line_id, tender_type, amount_applied_minor, change_due_minor?,
  external_reference?,                                  // present but redacted to '*****' if logged
  voucher_authority_redemption_id?,                     // opaque short string; safe to display
  state, applied_at?, refused_at?, reversed_at?, reversal_pending_since?,
  refusal_reason?,                                      // generic enum; renderer maps to generic copy
  apply_order
}
```

**No voucher token, no voucher balance, no voucher-side metadata
crosses this bridge** (FR-017, OQ-PLAN-7).

### `payments.read`

One-shot read of the current attempt state. Identical projection to
`payments.subscribe` but non-streaming.

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3.

**Request:** `{ payment_attempt_id: UUID v4 }`.
**Response:** same shape as `payments.subscribe` (no idempotency key
required — pure read).

### `payments.discardOnSessionEnd` *(internal, main-process-only)*

Called by the main process when an operator session ends with a
`started` attempt still bound. Transitions the attempt to `failed`
with reason `operator_session_terminated`. **Not exposed to the
renderer.**

**Effects:**

- Transitions `payment_attempts.state = failed` with
  `failure_reason = 'operator_session_terminated'`.
- Emits `payment.failed` with the session-end attribution.
- **Already-applied `TenderLine`s are reversed using the same LIFO
  + reversal_pending pattern as `payments.cancel`.**

## `tender.*` namespace

### `tender.apply`

Applies a tender line to a `started` payment attempt.

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3 (cash + external_card_terminal); Slice 4 enables
voucher.

**Request:**

```text
{
  payment_attempt_id: UUID v4,
  tender_type: 'cash' | 'external_card_terminal' | 'internal_voucher',
  amount_applied_minor: integer (non-negative),
  external_reference?: string (regex ^[A-Z0-9]{0,6}$, optional),   // only for external_card_terminal
  voucher_code?: string,                                            // only for internal_voucher; validated main-side
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', tender_line_id: UUID v4, applied_at: UTC timestamp, change_due_minor?: integer }
| { kind: 'refused', reason: 'no_session' | 'role_denied' | 'wrong_owner' | 'attempt_terminal' | 'invalid_input' | 'non_cash_overpayment_refused' | 'voucher_not_found' | 'voucher_expired' | 'voucher_cancelled' | 'voucher_already_redeemed' | 'voucher_tenant_mismatch' | 'voucher_branch_mismatch' | 'dependency_unavailable' | 'idempotency_payload_mismatch' | 'tender_not_yet_supported' }
```

**Effects (per tender_type):**

| `tender_type` | Effects |
|:--|:--|
| `cash` | Writes `payment_tender_lines` row with `state='applied'`. Computes `change_due_minor` if over-tendered. Writes `payment_action_outbox` row. Emits `tender.applied`. |
| `external_card_terminal` | Validates `external_reference` regex main-side. Refuses overpayment with `non_cash_overpayment_refused`. Writes line + outbox. Emits `tender.applied` with `external_reference` redacted to `*****` in any non-payload log. |
| `internal_voucher` | (Slice 4 only). Calls `vouchers.validate` (Contract V-A). On success: writes line with `state='applied'`, stores `voucher_redemption_intent_token`. On any voucher refusal: writes line with `state='refused'`, stores `refusal_reason`. Emits `tender.applied` or `tender.refused`. **Until Slice 4 commissions:** `internal_voucher` returns `tender_not_yet_supported`. |

### `tender.reverse`

Reverses an `applied` tender line. Idempotent via `idempotency_key`.

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3 (cash + external_card_terminal); Slice 4 enables
voucher reverse + `reversal_pending` resolver.

**Request:**

```text
{
  tender_line_id: UUID v4,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', reversed_at: UTC timestamp, state: 'reversed' | 'reversal_pending' }
| { kind: 'refused', reason: 'no_session' | 'role_denied' | 'wrong_owner' | 'line_not_applied' | 'idempotency_payload_mismatch' }
```

**Effects (per tender_type):**

| `tender_type` | Effects |
|:--|:--|
| `cash` | Transitions to `reversed`. No till impact recorded (drawer impact OQ-DRW-1..4 deferred). Emits `tender.reversed`. |
| `external_card_terminal` | Transitions to `reversed`. Emits `tender.reversed` with `manual_void_required: true` audit-payload flag. |
| `internal_voucher` *(Slice 4)* | Calls `vouchers.reverse` (Contract V-A). Success → `reversed`. Unreachable authority → `reversal_pending`; deferred resolver runs later. |

### `tender.read`

One-shot read of a single line. Same projection as
`payments.subscribe`'s `TenderLineRendererView`.

**Roles:** `cashier`, `manager`, `admin`.
**Slice:** 3.

## `vouchers.*` namespace *(Slice 4, Contract V-A)*

These handlers are **commissioned only at Slice 4** under §A2 +
§A4. They are recorded here for forward reference.

| Handler | Purpose | Backed by |
|:--|:--|:--|
| `vouchers.validate` | Validates a voucher code against Data-Pulse-2 for a specific applied amount. **Request includes** `applied_amount_minor: integer` (the amount the cashier wants to apply, capped client-side at `remaining_balance_at_apply_time`). Authority refuses if `applied_amount_minor > authoritative_voucher_balance` OR `applied_amount_minor > remaining_balance_at_apply_time` (cap enforced authority-side per R-7's refuse-not-cap rule; no residual-voucher reconciliation in v1). On success, returns the non-sensitive `redemption_intent_token`. On refusal, returns a closed-set reason. | `POST /vouchers/validate` (Data-Pulse-2) |
| `vouchers.redeem` | Atomically redeems an intent token at payment confirmation. Returns `voucher_authority_redemption_id` on success. | `POST /vouchers/redeem` (Data-Pulse-2) |
| `vouchers.reverse` | Reverses a previously-redeemed voucher line on cancel. | `POST /vouchers/reverse` (Data-Pulse-2) |

**Until Slice 4 ships**, the `internal_voucher` slot in tender
selection is **reserved-but-disabled** (FR-001); invoking it returns
`tender_not_yet_supported`.

## Deferred reversal *(Slice 4)*

A `reversal_pending` `TenderLine` is resolved by a background
deferred-reversal resolver (see [../research.md](../research.md) R-13)
that runs on:

1. **App start** — scans for `state = 'reversal_pending'` lines and
   retries `vouchers.reverse`.
2. **Network-restore signal** from the 003 connection-state surface.
3. **Cashier-initiated retry** via a Slice 4 manager / cashier
   incident UI (TBD design).

On success the line transitions to `reversed` and a `tender.reversed`
audit event is emitted; the `reversal_pending_since` timestamp is
preserved for incident reconstruction.

## Renderer-visible fields — minimisation rule

The renderer NEVER receives:

- Clerk JWT, device_token, device_token_attestation, PINs, PIN hashes,
  passwords, backend_session_id, raw envelope payload (only the
  fields enumerated in 005 §"Field shape (v1)" cross the bridge from
  005 → 006 → renderer).
- Voucher redemption intent tokens (`voucher_redemption_intent_token`
  stays main-side).
- Voucher balance, voucher-issuance metadata, loyalty-campaign
  internals, voucher holder PII, cross-cart voucher state.
- Cardholder data of any kind (FR-008 / FR-040 — none is captured at
  all; the bridge cannot leak what it does not collect).
- Manager identity on force-fail (FR-021 last clause).
- Raw audit-event payloads (renderer reads `payments.subscribe` /
  `payments.read` projections, not audit rows directly).
- `idempotency_payload_mismatch` raw payload-diff details (refusal
  is generic; mismatch detail is logged main-side).

Sensitive fields that **MAY** cross to the renderer (with redaction
rules):

- `external_reference` — rendered as-is to the cashier (it's their
  own input); redacted to `*****` in every log sink.
- `voucher_authority_redemption_id` — opaque short string returned by
  `vouchers.redeem`; safe to display for receipt-handoff and audit
  correlation; never contains voucher balance or holder data.

  above matches `src/shared/bridge-api.ts` TypeScript definitions

  appear in Sentry / console / log-file samples.
