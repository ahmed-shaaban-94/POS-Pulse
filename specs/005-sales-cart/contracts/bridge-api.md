# Contract: `cart.*` Bridge API

**Feature ID:** 005-sales-cart
**Plan:** [../plan.md](../plan.md)
**Spec:** [../spec.md](../spec.md)
**Data model:** [../data-model.md](../data-model.md)
**Created:** 2026-05-14
**Constitution version pinned:** v1.5.1

> The `cart.*` preload-bridge namespace is the **trust boundary** between
> the renderer and the main process for cart operations (Constitution
> Principle III; AD-1). Every handler in this contract is gated at the
> bridge surface — renderer-side checks are secondary UX defence only and
> are NEVER load-bearing.

---

## Bridge gating — `requireOperatorSession`

Every handler in the `cart.*` namespace MUST begin with:

```text
const session = requireOperatorSession({
  role?: 'cashier' | 'manager' | 'admin',
  cart_id?: string,
})
```

The helper lives in `src/main/cart/` (post-§A0) and delegates to 004's
`src/main/operator/role-enforcement.ts`. Failure modes:

| Condition | Result |
|:--|:--|
| No active session | generic refusal (`{ kind: 'refused', reason: 'no_session' }`) per 004 FR-005 / FR-016. |
| Wrong role for this handler | generic refusal (`{ kind: 'refused', reason: 'role_denied' }`). |
| `cart_id` given but cart's `operator_session_id` does not match `session.operator_session_id` AND handler is not in the manager-attributable set | generic refusal (`{ kind: 'refused', reason: 'wrong_owner' }`). |
| Tenant / branch / terminal mismatch between session and cart | generic refusal (`{ kind: 'refused', reason: 'tenant_isolation' }`) per FR-002. |
| Cart is in `frozen_handed_off` AND handler is mutating | generic refusal (`{ kind: 'refused', reason: 'frozen' }`) per FR-035; emits `cart.handoff_to_payment`-adjacent diagnostic log. |
| Cart is `cancelled` | generic refusal (`{ kind: 'refused', reason: 'closed' }`) per FR-006. |

**All refusals use generic wording.** No factor-distinguishing variants
(004 NFR-003 / PR-2 inherited). The refusal `reason` lives in the bridge
payload for diagnostic logging (with redaction); it is NOT echoed to the
cashier as-is (the renderer translates a generic "this action isn't
allowed right now" UX).

## Idempotency — `action_id` (UUID v4)

Every **mutating** handler accepts an `idempotency_key: string` (UUID v4)
generated by the renderer at the moment of intent. The bridge:

1. Looks up `cart_action_outbox` by `action_id = idempotency_key`.
2. If found AND the payload is identical: no-op; returns the original
   outcome (FR-018 / P5).
3. If found AND the payload differs: refuses with
   `{ kind: 'refused', reason: 'idempotency_payload_mismatch' }` (P5; UUID
   identifies the *operation*, not the *line*).
4. If not found: applies the action AND writes the outbox row in the
   same transaction.

The renderer MUST NOT generate a new `idempotency_key` on retry — the
same UUID must accompany every retry of the same intended operation.

## Handler list (canonical names)

### `cart.create`

Creates a new draft cart bound to the current operator session.

**Roles:** `cashier`, `manager`, `admin`.

**Request:**

```text
{ idempotency_key: UUID v4 }
```

**Response:**

```text
| { kind: 'ok', cart_id: UUID v4 }
| { kind: 'refused', reason: '...' }
```

**Effects:** writes `carts` row with `state = empty`; writes
`cart_action_outbox` row with `action_kind = cart.create`. No audit
emission (non-sensitive per FR-027).

---

### `cart.lines.add`

Adds a line item to a cart. **Q4 merge default applies:** if a
non-removed line for the same `item_ref` exists, the bridge merges into
it (increments `quantity`, advances `version`) and writes a
`cart.line.merge` outbox row; otherwise it inserts a new line and
writes a `cart.line.add` outbox row.

**Roles:** `cashier`, `manager`, `admin`.

**Request:**

```text
{
  cart_id: UUID v4,
  item_ref: string,
  quantity: positive integer,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| {
    kind: 'ok',
    line_id: UUID v4,             // the surviving line (merged or new)
    merged: boolean,              // true if Q4 merge path was taken
    version: monotonic integer,   // post-mutation
  }
| { kind: 'refused', reason: '...' }
```

**Effects:**

- **New line path:** writes `cart_lines` row; sets `display_name` and
  `unit_price_minor` from the R7 `cart.resolveItemRef` seam; writes
  `cart_action_outbox` row with `action_kind = cart.line.add`.
- **Merge path (Q4):** increments existing `cart_lines.quantity`,
  recomputes `line_subtotal_minor`, advances `version`; writes
  `cart_action_outbox` row with `action_kind = cart.line.merge`. The
  surviving line's `unit_price_minor` and `note` are NOT changed by the
  merge.
- Cart transitions to `editing` if it was `empty`.
- No audit emission (non-sensitive per FR-027).

**Catalogue resolution refusal** (R7): if
`cart.resolveItemRef(item_ref)` returns `refused`, this handler
propagates the refusal.

---

### `cart.lines.update`

Changes the quantity of an existing line (increment, decrement, or set
absolute). `set(0)` is delegated to `cart.lines.remove` (FR-016).

**Roles:** `cashier`, `manager`, `admin`.

**Request:**

```text
{
  cart_id: UUID v4,
  line_id: UUID v4,
  op: 'increment' | 'decrement' | 'set',
  delta?: positive integer,                 // for increment / decrement
  absolute?: non-negative integer,          // for set; if 0 → routed to remove
  version: monotonic integer,               // last-known
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', version: monotonic integer }
| { kind: 'refused', reason: 'stale_version' | '...' }
```

**Effects:** updates `cart_lines.quantity`; recomputes
`line_subtotal_minor`; advances `version`; writes `cart_action_outbox`
row with `action_kind = cart.line.update`. Stale-version refusal is
governed by FR-019.

---

### `cart.lines.remove`

Soft-removes a line. Sets `removed_at` rather than deleting the row
(audit continuity).

**Roles:** `cashier`, `manager`, `admin`.

**Request:**

```text
{
  cart_id: UUID v4,
  line_id: UUID v4,
  version: monotonic integer,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok' }
| { kind: 'refused', reason: 'stale_version' | '...' }
```

**Effects:** sets `cart_lines.removed_at`; writes
`cart_action_outbox` row with `action_kind = cart.line.remove`. Replay
with the same `idempotency_key` is a no-op (FR-018).

---

### `cart.lines.setNote`

Sets or clears the free-text note on a line.

**Roles:** `cashier`, `manager`, `admin`.

**Request:**

```text
{
  cart_id: UUID v4,
  line_id: UUID v4,
  note: string | null,                      // ≤ 200 chars (Q1); null clears
  version: monotonic integer,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', version: monotonic integer }
| { kind: 'refused', reason: 'note_too_long' | 'note_forbidden_pattern' | 'stale_version' | '...' }
```

**Effects:** updates `cart_lines.note`; advances `version`; writes
`cart_action_outbox` row with `action_kind = cart.line.note_set`. The
bridge enforces:

- **Length cap** at 200 chars (Q1; FR-020). Partial overwrite forbidden.
- **Forbidden patterns** per the project's existing allowlist (NFR-006;
  matches 004 PR-1). Generic refusal — pattern NOT echoed.

No audit emission (non-sensitive per FR-027).

---

### `cart.discountPlaceholders.add`

Adds a discount placeholder to a line.

**Roles:** `cashier`, `manager`, `admin`. **Manager attribution required**
when the placeholder's magnitude exceeds the Q2 tenant-configured
threshold (percentage of `line_subtotal_minor`, per-line).

**Request:**

```text
{
  cart_id: UUID v4,
  line_id: UUID v4,
  placeholder_kind: string,                 // opaque token (FR-024)
  attribution_operator_id?:                 // required if magnitude > threshold
    Clerk-backed identity,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', placeholder_id: UUID v4, requires_manager_attribution: boolean }
| { kind: 'refused', reason: 'manager_attribution_required' | '...' }
```

**Effects:** writes a row to `cart_line_discount_placeholders` (the
fourth cart-introduced table per data-model.md); writes
`cart_action_outbox` row with `action_kind =
cart.discount_placeholder.add`. If `requires_manager_attribution` is
true and a manager attribution is recorded, ALSO emits an `audit_events`
row with `action_category = cart.discount.above_threshold` (sensitive
per FR-023, FR-026).

The cart layer **does NOT compute the discounted amount.** Magnitude is
classified "above threshold yes/no" by reading the tenant configuration
at apply-time; the *value* of the discount is the future payment /
checkout feature's responsibility.

---

### `cart.discountPlaceholders.remove`

Removes a discount placeholder from a line. If the placeholder originally
required manager attribution, the remove also requires manager
attribution (mirrors the add rule).

**Roles:** `cashier`, `manager`, `admin` (manager attribution required
for above-threshold placeholders).

**Request:**

```text
{
  cart_id: UUID v4,
  placeholder_id: UUID v4,
  attribution_operator_id?:
    Clerk-backed identity,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok' }
| { kind: 'refused', reason: '...' }
```

**Effects:** deletes the placeholder row; writes `cart_action_outbox`
row with `action_kind = cart.discount_placeholder.remove`. Audit
emission only if the original add required attribution.

### `cart.void`

Voids a cart. The semantics depend on the cart's state:

- **Pre-handoff (state = `editing` / `empty` / `discount_pending_attribution`):**
  cashier may void their own cart (non-sensitive lifecycle event;
  `cancellation_reason = 'cashier_voided'`; no audit emission per
  FR-031). Manager / admin may void any cart in branch.
- **Post-handoff (state = `frozen_handed_off`):** **manager / admin
  only.** Cashier-initiated post-handoff void is refused generically
  (FR-032). On manager approval, transitions to `cancelled` with
  `cancellation_reason = 'manager_voided_post_handoff'`; emits
  `audit_events` row with `action_category = cart.cancel.post_handoff`
  (sensitive per FR-033).

**Roles:** `cashier` (own pre-handoff only); `manager`, `admin` (any cart
in branch).

**Request:**

```text
{
  cart_id: UUID v4,
  attribution_operator_id?:                 // required for post-handoff
    Clerk-backed identity,
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok' }
| { kind: 'refused', reason: 'manager_attribution_required' | '...' }
```

**Effects:** transitions `carts.state` to `cancelled`; sets
`cancelled_at` and `cancellation_reason`; writes `cart_action_outbox`
row with `action_kind = cart.void` (pre-handoff) or
`cart.cancel.post_handoff` (post-handoff). Post-handoff path also emits
the `audit_events` row.

---

### `cart.handoff`

Constructs the `PaymentIntentEnvelope`, freezes the cart, and emits the
handoff audit event. See [`./handoff-envelope.md`](./handoff-envelope.md)
for the envelope shape and the construction algorithm.

**Roles:** `cashier` (must be the cart's `owning_operator_id`), `manager`,
`admin`.

**Request:**

```text
{
  cart_id: UUID v4,
  per_line_versions: { line_id: UUID v4, version: monotonic integer }[],
  idempotency_key: UUID v4,
}
```

**Response:**

```text
| { kind: 'ok', envelope: PaymentIntentEnvelope }
| { kind: 'refused', reason: 'empty_cart' | 'stale_version' | '...' }
```

**Effects:** see handoff-envelope.md. Audit emission: `action_category =
cart.handoff_to_payment` (sensitive per FR-026; SC-005).

---

### `cart.subscribe`

Push-style updates for the renderer's `cartStore` (optional; the renderer
MAY also poll). The handler returns an Observable-like stream of:

```text
{ cart_id: UUID v4, state: enum, last_action_id: UUID v4 }
```

The bridge MUST NOT push line-level deltas through this channel —
renderer reads via `cart.read` on each transition (defined in S1).

## R7 seam — `cart.resolveItemRef`

```text
cart.resolveItemRef({ item_ref: string })
  → | { kind: 'ok', display_name: string, unit_price_minor: integer, version: string }
    | { kind: 'refused', reason: 'unknown_item' | 'disabled' | 'no_connection' | 'generic' }
```

In Slices S1 + S2 (gated on §A1), tests inject a fixture resolver
returning a small known SKU set. Production code paths refuse generically
when no real catalogue is available. Once a future item-catalogue feature
ships, this seam is implemented by that feature; 005 does not change.

## Discarded-on-session-end emission (Q3 + Q5 path)

When the bound operator session ends — sign-out, inactivity per 004
FR-009, takeover per 004 FR-013, or forced-close per 004 FR-024 — the
operator-session emitter (from 004) fires a session-end event. 005's
main-process subscriber (`src/main/cart/session-end-handler.ts`,
post-§A0) transactionally:

1. Looks up any draft cart bound to that session.
2. If found: transitions `state → cancelled`; sets
   `cancellation_reason = 'session_ended'`; writes a
   `cart_action_outbox` row with `action_kind =
   cart.discarded_on_session_end` and `acting_operator_id = the cashier
   whose session ended`.
3. Emits an `audit_events` row with `action_category =
   cart.discarded_on_session_end` (sensitive per Q5 + FR-026).

The session-end emitter MUST NOT block on cart discard (the session
end takes priority — Q5 emission is queued in the local outbox if the
discard write fails partially). The cart is never observable by a
subsequent cashier on the same terminal (Q3, FR-007, §Edge Cases).

## Test surface required at S1 and S2 (informational)

The bridge-side test plan (referenced by `/speckit-tasks` later) MUST
cover, for every handler in this contract:

- **Happy path** with a valid session, valid payload, correct role.
- **No-session refusal** (generic).
- **Wrong-role refusal** (generic).
- **Wrong-owner refusal** (where applicable; generic).
- **Tenant-isolation refusal** (generic; FR-002, SC-007).
- **Idempotency replay** with the same `action_id` + same payload (no-op).
- **Idempotency conflict** with the same `action_id` + different payload (refused).
- **Stale-version refusal** for `cart.lines.update`, `remove`, `setNote`, `handoff`.
- **Frozen-cart refusal** for every mutating handler when state is `frozen_handed_off` (FR-035).
- **Q4 merge path** for `cart.lines.add` (existing line for the same `item_ref` → merge).
- **Note length cap** (Q1, 200 chars) and **forbidden-pattern refusal** for `cart.lines.setNote`.
- **Manager-attribution required** for above-threshold discount placeholder add / remove and post-handoff void.
- **Cross-process redaction smoke** (NFR-006): `note` content, forbidden patterns, and credential fragments must NOT appear in logs / Sentry / support bundles.

Coverage gate: ≥ 95 % on the bridge-side gate (NFR-004 + plan Test
Strategy).
